#

如果一个 Personal Agent 每天让你打开 20 次，另一个 Personal Agent 每天只需要和它交流两三次，哪一个产品做得更好？

按照过去互联网产品的评价方式，答案似乎很明显。前者拥有更高的打开频率、更长的使用时长、更好的 Engagement，如果反映到数据上，它的 DAU、Session、PV 甚至留存数据可能都会更加漂亮。

但换个角度，答案可能完全相反。

第一个 Agent 每天提醒你查看邮件、确认日程、选择航班、确认酒店、审批任务。它确实每天都在和你互动，但每一件事情最终还是需要你自己判断。第二个 Agent 已经知道你的工作习惯、差旅偏好、预算范围和做事原则，它可以自己处理普通邮件、协调可以调整的会议，根据你的偏好安排差旅，只有真正需要你做决定的时候才来找你。

你每天可能只和第二个 Agent 交流两三次，但它显然更接近我们真正想要的 Personal Agent。这里出现了一个很有意思的反差：

一个 Agent 做得越好，我们花在它上面的时间，可能反而越少。

过去二十年互联网形成的一套产品增长逻辑，到了 Agent 时代可能需要重新审视。互联网时代，产品争夺用户的注意力，并围绕注意力构建“流量飞轮”；Agent 时代，一个真正优秀的 Personal Agent 应该帮助用户保护注意力，并围绕人与 Agent 之间不断加深的信任关系，构建一种完全不同的飞轮——信任飞轮。

一、互联网时代，本质上是一场注意力战争
#

过去二十年的互联网商业，有一个非常重要的基础资源：Attention，注意力。 用户在哪里，流量就在哪里；流量在哪里，广告、内容、交易和商业价值就更容易在哪里发生。所以互联网产品长期以来都在解决一个核心问题：怎样让用户进来，并尽可能长时间地留下来？

从门户网站，到搜索引擎，再到社交网络、移动互联网和短视频，产品形态不断变化，但大量产品的底层增长逻辑非常相似。Push 把你叫回来，红点提醒你还有东西没看，推荐算法不断寻找你可能感兴趣的下一条内容，无限滚动让信息流永远没有尽头，自动播放则尽量消除“要不要继续看”的决策过程。这些产品机制各自解决不同的问题，但从商业角度看，它们共同推动了一件事：更多打开、更多停留、更多互动。

于是我们逐渐建立起一整套围绕注意力的产品指标：DAU、MAU、PV、Session、使用时长、次日留存、七日留存、月留存……而在这些指标背后，是互联网时代非常典型的一套增长飞轮：

更多用户 → 更多使用 → 更多内容、数据和交易 → 更好的产品体验与供给 → 更高的留存和传播 → 更多用户。

这就是互联网时代的流量飞轮。不同类型的互联网产品，飞轮当然并不完全一样，但它们有一个共同特征：产品希望用户不断回来，并产生更多使用行为。从某种意义上讲，互联网产品希望成为用户注意力的目的地。 用户关系的广度、使用频率和注意力占有，也因此成为互联网产品非常重要的增长来源。

但 Agent 的逻辑恰恰相反。

二、Agent 时代，不应该继续争夺注意力，而应该保护注意力
#

传统 App 和 Agent 最大的区别，不是有没有聊天框，也不是有没有接入大模型，而是谁才是数字世界真正的操作者。

传统软件的基本结构是 Human → App → Action。人需要打开 App，寻找功能，点击按钮，输入信息，然后一步一步完成任务。即使移动互联网已经把这些操作做得非常简单，人仍然是整个过程的主要操作者。

Agent 的关系则开始变成 Human → Intent → Agent → Apps / Web / API → Action。人越来越少地告诉计算机“下一步点击哪里”，而越来越多地告诉 Agent“我想完成什么”。至于打开哪个网站、调用什么服务、填写什么表单、比较哪些方案、执行多少步骤，开始由 Agent 自己决定。

Agent 真正帮助人节省的东西，也就不只是操作时间，而是一种更加稀缺的资源：人的注意力。

想想我们每天在数字世界里消耗了多少注意力。查看邮件，判断哪一封重要；打开日历，协调会议时间；比较机票和酒店；处理各种通知；在不同 App 之间切换；跟进任务状态；确认订单；回复大量并不真正需要深度思考的信息。每一件事情可能只需要几分钟，但它们不断打断我们的注意力。真正消耗人的，往往不是某个任务需要 5 分钟，而是一天几十次从一个上下文切换到另一个上下文。

一个真正优秀的 Personal Agent，应该站在用户和复杂数字世界之间，帮助用户完成大量这样的判断、过滤和执行。邮件、消息、会议、通知、任务、网页、应用状态，甚至其他 Agent 产生的信息，都应该先经过 Personal Agent。Agent 自己能够处理的，就直接处理；真正需要人的判断、创造力、价值选择或者承担责任的事情，再交还给人。

所以 Agent 不应该只是一个更高效的信息入口，它还应该成为人的 Attention Filter——注意力过滤器。

互联网产品经常思考的是“怎样让用户多花 30 分钟”，Agent 产品则应该思考“怎样替用户省掉这 30 分钟”。互联网产品争夺的是 Attention Captured，Agent 产品创造的则应该是 Attention Saved。

三、为什么保护注意力的前提一定是信任？
#

既然 Agent 可以替我们处理这么多事情，为什么今天我们仍然需要不断确认？原因很简单：我们还不够信任它。

假设 Agent 帮你预订一次出差。它找到航班以后问你“这个航班可以吗”，你确认；然后找到酒店，又问“这个酒店可以吗”，你再次确认；接下来是房型、价格、时间、付款方式。最后 Agent 的确完成了整个差旅预订，但你仍然参与了几乎所有关键步骤。这时候 Agent 节省的注意力，可能并没有想象中那么多。

过去是你自己做事情，现在变成了你监督 AI 做事情。如果每一步都需要人检查，每一个决定都需要人确认，那么 Agent 只是从“工具”变成了一个需要管理的“数字实习生”。所以真正的 Attention Saved，必须建立在 Trust 之上。

人与 Agent 的关系会经历一个逐渐放权的过程。刚开始，因为信任很低，Agent 每做一步都需要用户确认；使用一段时间后，用户发现 Agent 越来越了解自己的偏好，表现也足够稳定，于是开始允许它完成一些低风险任务，只在关键节点确认；再往后，Agent 只需要在异常情况下回来找用户；最后，对于那些已经高度熟悉的任务，用户可以直接说：“这种事情以后你自己处理。”

于是出现一个非常重要的关系：

Trust 越高 → Human Intervention 越少 → Attention Saved 越多。

信任不是 Personal Agent 的附加价值，而是 Agent 能够保护用户注意力的前提。

没有信任，Agent 只能帮助人操作；有了信任，Agent 才能真正替人承担。

四、从流量飞轮到信任飞轮
#

一个新的 Personal Agent 刚刚进入用户生活时，用户不可能第一天就把邮箱、日历、银行卡、工作文件和所有重要决定全部交给它。信任一定从小事情开始。

第一次可能只是“帮我整理一下今天的邮件”。Agent 做得不错，下一次变成“帮我把不重要的邮件处理掉”；继续表现稳定以后，用户开始说“普通邮件你直接处理，需要我决定的再告诉我”；再往后则可能变成“这类事情以后你自己处理”。

这个过程里，Agent 获得了越来越多和用户真实互动的机会。互动越多，它越了解用户的偏好、习惯、目标和边界；越了解用户，就越能够稳定地完成任务；任务完成得越稳定，用户就越信任它；信任越高，用户就越愿意把更多事情交给它；更多委托，又让 Agent 获得更多真实世界中的经验。

于是形成一个循环：

更多互动 → 更了解用户 → 更理解意图和边界 → 更稳定地完成任务 → 更多信任 → 更多委托 → 更高自主性 → 更少人工介入 → 保护更多注意力 → 更多真实任务和经验 → 进一步增强理解和信任。

这就是 Trust Flywheel——信任飞轮。

它和互联网时代的流量飞轮有一个本质差异：流量飞轮追求的是关系的广度，信任飞轮追求的是关系的深度。

互联网产品希望有更多用户进来，Personal Agent 不仅需要用户进来，更需要同一个用户愿意把越来越重要的事情留下来。互联网产品增长经常意味着 More Users × More Engagement，而 Personal Agent 的增长，更接近 More Users × Deeper Delegation。

Agent 产品的核心增长对象，也就不再只是 Engagement，而是 Delegation——委托。

五、Agent 真正需要增长的，是“委托深度”
#

怎样判断一个用户到底有多信任自己的 Agent？一个非常直接的方式，就是看他愿意把多重要的事情交给 Agent。

这可以形成一个简单的 Delegation Depth——委托深度。最浅的一层是“告诉我怎么做”，这时候 Agent 本质上仍然是一个 Answer Engine；再进一步是“帮我做一下”，Agent 开始参与执行，但用户仍然控制过程；然后是“这件事情你来处理”，Agent 获得完整任务；再往后变成“这种事情以后不用问我”，Agent 开始获得持续自主权；更进一步是“你自己判断怎么处理”，Agent 开始拥有一定决策权；最终甚至可能变成“这件事情你可以代表我处理”，Agent 获得某种 Representation。

从 Answer → Assist → Execute → Autonomous → Decide → Represent，这条路径描述的并不是模型能力越来越强，而是人愿意交出去的控制权越来越多。

所以对于 Personal Agent 来说，DAU 很重要，但它已经不足以描述真正的产品价值。一个每天使用 Agent 20 次、所有事情都需要自己确认的人，和一个每天只和 Agent 沟通两次、却已经把大量事务交给它自主处理的人，谁才是更深度的用户？

按照传统互联网指标，也许是前者；按照 Personal Agent 的逻辑，则是后者。

未来 Agent 产品可能需要一个完全不同的 North Star Metric：Delegation Depth。 衡量的不再只是用户用了多少次，而是：

用户敢把多少事情交给你。

六、Trust Budget：怎样把“我信任你”变成真正的自主权？
#

信任不能只是一个抽象的心理状态，产品最终必须把信任转化成具体权限。

现实世界里，我们一直在这么做。一个员工刚刚加入公司，你可能告诉他：“5000 元以内的采购，你自己决定。”合作一段时间以后变成：“5 万元以内不用找我确认。”合作几年以后则可能是：“这个项目预算你全权负责。”

我们不会因为“信任一个人”，就直接把所有权力交给他。信任总是有范围、有边界、有额度的，Agent 产品同样需要这样一个机制：Trust Budget——信任额度。

它不是传统软件简单的 Allow / Deny，而是“你可以自主做到什么程度”。例如 Money Budget 决定多少钱以内 Agent 可以自主支付；Data Budget 决定哪些数据可以访问；Action Budget 决定哪些操作可以直接执行；Communication Budget 决定 Agent 可以代表用户联系哪些人；Decision Budget 决定多重要的事情可以自主判断；Time Budget 则决定 Agent 可以在后台持续自主运行多久。

于是形成了一条很清晰的关系：

Trust 增加 → Trust Budget 增加 → Delegation 增加 → Autonomy 增加。

Agent 获得更多自主权以后，又会产生更多真实世界中的表现，重新影响用户对它的 Trust。Trust Budget，就是把“我信任你”转化成“你可以做到什么程度”的产品机制，也是信任飞轮真正能够转起来的一个关键齿轮。

七、从 DAU 到 Delegation：Agent 时代需要一套新的产品指标
#

互联网时代形成了一套非常成熟的产品指标体系。DAU 衡量每天有多少人来，使用时长衡量用户愿意把多少注意力留在产品里，Session 衡量用户回来多少次，留存率衡量用户会不会持续回来，转化率则衡量流量最终能不能变成交易。

这些指标背后其实隐含着一个共同的产品假设：用户更多地回来、更频繁地使用、停留更长时间，通常意味着产品创造了更大的价值。

但到了 Agent 时代，这个假设开始松动。

一个 Personal Agent 每天被打开 20 次，不一定比每天只被打开两次更好；用户在 Agent 上停留 60 分钟，也不一定比只花 5 分钟更有价值。恰恰相反，如果一个 Agent 已经足够了解用户，能够在后台自主完成大量工作，那么更少的打开、更短的使用时间、更少的人工介入，反而可能意味着它做得更好。

所以 Agent 产品并不是要放弃 DAU、留存率这些互联网指标，而是需要在它们之上建立一套新的指标体系。互联网指标主要衡量的是 Usage 和 Engagement，Agent 指标则应该更多衡量 Trust、Delegation 和 Attention Saved。

两套指标可以形成一个很有意思的对照：

这里真正发生变化的，并不是简单地把一套 KPI 换成另一套 KPI，而是指标优化的方向变了。

互联网产品希望 Time Spent 越高越好，而 Agent 产品应该追求 Attention Saved 越高越好；互联网产品希望用户产生更多 Actions，而 Agent 产品应该努力降低 Human Intervention Rate；互联网产品关心用户有没有回来，Agent 产品除了关心用户有没有回来，更应该关心用户有没有继续把事情交给它。

甚至 DAU 本身都需要被重新理解。对于一个成熟的 Personal Agent，最有价值的“活跃”可能不是用户打开了 Agent，而是 Agent 在用户授权范围内持续替用户完成工作。因此，相比传统的 Daily Active Users，未来还可以关注 Daily Delegating Users：每天有多少用户真正把任务交给 Agent，而不仅仅是打开它、问了一个问题。

Retention 也可以进一步变成 Delegation Retention。一个用户连续 30 天打开 Agent 聊天是一种留存，但一个用户连续 30 天都愿意把邮件整理、会议协调或者差旅安排交给 Agent，是另一种完全不同的留存。后者反映的不只是使用习惯，而是已经建立起来的信任关系。

在这些新指标中，最核心的仍然是三个：Delegation Depth、Human Intervention Rate 和 Attention Saved。 Delegation Depth 衡量用户敢把多重要的事情交给 Agent；Human Intervention Rate 衡量 Agent 完成一件事情需要把人叫回来多少次；Attention Saved 则衡量 Agent 最终替用户减少了多少信息筛选、上下文切换、判断、确认、跟进和重复操作。

这样一来，Agent 产品的 North Star Metric 会出现一个很有意思的反转。过去我们可能希望看到：

DAU ↑、Session ↑、Time Spent ↑、Actions ↑。

Agent 产品则更应该希望看到：

Delegation Depth ↑、Trust Budget ↑、Attention Saved ↑、Human Intervention Rate ↓。

互联网产品衡量“用户为产品做了多少”，Agent 产品更应该衡量“产品替用户做了多少”。

这才是从互联网产品走向 Agent 产品以后，指标体系真正需要发生的变化。

八、信任飞轮，可能成为 Personal Agent 真正的护城河
#

今天谈 AI 产品的护城河，很容易想到模型：谁的模型更聪明，谁的推理能力更强，谁的 Computer Use 更稳定，谁能接更多工具。这些当然重要，但长期来看，模型会升级，工具可以接入，基础能力也会越来越商品化。

有一样东西却没有那么容易迁移：一个 Agent 和一个人长期相处以后形成的信任关系。

它知道你的工作习惯，知道你喜欢什么、讨厌什么，知道什么事情你愿意冒险、什么事情必须谨慎，知道哪些人可以直接回复，也知道哪些话题必须回来问你。更重要的是，你也知道它过去做过什么、在哪些事情上可靠、哪些事情还需要监督。

这是一段双方共同形成的历史，包括偏好、边界、授权习惯、风险容忍度和长期互动积累的经验。这些东西最终可能共同形成一个非常独特的 Personal Trust Model。

所以未来 Personal Agent 真正的护城河，可能不只是“我的 Agent 比你的 Agent 聪明多少”，而是：

用户已经敢把多少事情交给我的 Agent？

当用户已经从“帮我查一下”，走到“帮我做一下”，再走到“这种事情以后你自己处理”，人与 Agent 之间建立的就不再只是产品使用习惯，而是一种长期信任关系。

九、互联网争夺注意力，Agent 应该保护注意力
#

回到文章最开始的问题：为什么一个每天只需要打开两三次的 Agent，可能比每天打开 20 次的 Agent 更成功？

因为我们正在用旧时代的指标理解一个新的产品形态。

互联网时代，我们不断想办法让用户进入产品；Agent 时代，一个真正优秀的产品，应该努力让用户越来越少地介入产品。互联网产品希望占据人的注意力，Personal Agent 应该保护人的注意力。互联网产品构建的是流量飞轮，Personal Agent 真正需要构建的，则是信任飞轮。

这两个时代甚至可以用两组完全不同的增长逻辑来概括：

互联网时代：Attention → Engagement → Traffic → Monetization。

Agent 时代：Trust → Delegation → Autonomy → Attention Saved。

流量飞轮解决的是“怎样让更多人来”，信任飞轮解决的是“怎样让一个人敢把更多事情留下来”。前者追求关系的广度，后者追求关系的深度；前者希望用户更多地使用产品，后者则希望用户越来越不用操心。

所以，一个真正优秀的 Personal Agent 最终带给用户的感觉，也许不是“这个 AI 帮我完成了很多事情”，而是一句更加简单的话：

“这些事情，我已经不用操心了。”

当 Agent 开始替我们承担越来越多数字世界中的琐事，一个更加有意思的问题也随之出现：当人重新拿回自己的注意力以后，我们应该把它放在哪里？
